# Open exercise databases, muscle taxonomies and data models for a personal gym app

Research date: 2026-09-26. All GitHub "last push" dates and licence names below were read directly from the GitHub REST API (`api.github.com/repos/...`) on this date; licence strings are quoted exactly as GitHub/SPDX reports them.

## Key Question 1: Which open exercise datasets exist (record count, fields, muscle taxonomy, licence, URL, last update, images)?

### Takeaway
There are two genuinely "free to embed" datasets with a real taxonomy: yuhonas/free-exercise-db (800+ exercises, JSON, The Unlicense/public domain, images included, last push 2026-08-30) and the wger exercise database (912 exercise bases / 3,373 translations, CC-BY-SA-4 by default, public JSON API, last push 2026-09-25). Everything else is either smaller (Open ExerciseDB 300+, rthepen 630, exercemus), carries attribution/media restrictions (everkinetic CC-BY-SA-4.0, hasaneyldrm MIT data + Gym visual media terms, RepDB attribution + no-redistribution), or is commercial (ExerciseDB one-time $199/$599, MuscleWiki API $10–$199.99/month with no offline use).

## Key Question 2: What muscle taxonomies do datasets use and how do they map to coarse body parts? Is there a well-regarded mapping table?

### Takeaway
Taxonomies range from 15 Latin-named muscles (wger) and 17 lay names (free-exercise-db) to 39 anatomical heads (Liftosaur) and 29 slugs (rthepen); the most useful published mapping to coarse body parts is Liftosaur's `screenMuscleToMuscleMapping`, which folds 39 muscles into exactly 11 screen groups (shoulders, triceps, back, abs, glutes, hamstrings, quadriceps, chest, biceps, calves, forearms) — the same 11 body parts requested for the app.

### Cited Findings
- free-exercise-db uses 17 muscle values: abdominals, abductors, adductors, biceps, calves, chest, forearms, glutes, hamstrings, lats, lower back, middle back, neck, quadriceps, shoulders, traps, triceps — [schema.json](https://raw.githubusercontent.com/yuhonas/free-exercise-db/main/schema.json)
- wger uses 15 anatomical muscles (see KQ1) with `name_en` filled for only 9 of them ("Biceps", "Shoulders", "Chest", "Triceps", "Abs", "Calves", "Glutes", "Quads", "Hamstrings", "Lats"; Serratus anterior, Trapezius, Brachialis, Obliquus externus abdominis and Soleus have empty English names) — [wger muscle endpoint](https://wger.de/api/v2/muscle/?limit=50); and 8 coarse categories (Abs, Arms, Back, Calves, Cardio, Chest, Legs, Shoulders) — [wger exercisecategory](https://wger.de/api/v2/exercisecategory/)
- Liftosaur's verbatim `screenMuscleToMuscleMapping`: shoulders = "Deltoid Anterior", "Deltoid Lateral", "Deltoid Posterior", "Infraspinatus", "Teres Major", "Teres Minor"; triceps = "Triceps Brachii"; back = "Erector Spinae", "Latissimus Dorsi", "Levator Scapulae", "Trapezius Lower Fibers", "Trapezius Middle Fibers", "Trapezius Upper Fibers", "Sternocleidomastoid", "Splenius"; abs = "Obliques", "Rectus Abdominis", "Iliopsoas"; glutes = "Gluteus Maximus", "Gluteus Medius", "Tensor Fasciae Latae"; hamstrings = "Adductor Magnus", "Adductor Brevis", "Adductor Longus", "Hamstrings"; quadriceps = "Adductor Brevis", "Adductor Longus", "Pectineous", "Quadriceps", "Sartorius"; chest = "Pectoralis Major Clavicular Head", "Pectoralis Major Sternal Head", "Serratus Anterior"; biceps = "Biceps Brachii", "Brachialis"; calves = "Gastrocnemius", "Soleus", "Tibialis Anterior"; forearms = "Brachioradialis", "Wrist Extensors", "Wrist Flexors"; an inverse `muscleToScreenMuscleMapping` and `Muscle_getMusclesFromScreenMuscle()` exist — [liftosaur muscle.ts](https://raw.githubusercontent.com/astashov/liftosaur/master/src/models/muscle.ts)
- Liftosaur exercise metadata uses `targetMuscles` (primary) and `synergistMuscles` (secondary), e.g. benchPress target ["Pectoralis Major Sternal Head"], synergists ["Deltoid Anterior","Pectoralis Major Clavicular Head","Triceps Brachii"]; lateralRaise target ["Deltoid Lateral"] — [liftosaur exercise.ts](https://raw.githubusercontent.com/astashov/liftosaur/master/src/models/exercise.ts)
- Hevy's API `muscle_group` enum (20 values): abdominals, shoulders, biceps, triceps, forearms, quadriceps, hamstrings, calves, glutes, abductors, adductors, lats, upper_back, traps, lower_back, chest, cardio, neck, full_body, other — [Hevy OpenAPI copy in hevy-mcp](https://raw.githubusercontent.com/chrisdoc/hevy-mcp/main/openapi-spec.json); Hevy's public library filters on 15 of these: Chest, Shoulders, Biceps, Triceps, Upper Back, Lower Back, Lats, Forearms, Abdominals, Neck, Quadriceps, Hamstrings, Glutes, Traps, Calves — [Hevy exercises](https://www.hevyapp.com/exercises/)
- workout.cool's `ExerciseAttributeValueEnum` muscle values: BICEPS, SHOULDERS, CHEST, BACK, GLUTES, TRICEPS, HAMSTRINGS, QUADRICEPS, FOREARMS, CALVES, TRAPS, ABDOMINALS, NECK, LATS, ADDUCTORS, ABDUCTORS, OBLIQUES, GROIN, FULL_BODY, ROTATOR_CUFF, HIP_FLEXOR, ACHILLES_TENDON, FINGERS — [workout-cool schema.prisma](https://raw.githubusercontent.com/Snouzy/workout-cool/main/prisma/schema.prisma)
- ExerciseDB-style data uses a two-level scheme: coarse `bodyPart` (waist, upper legs, back, lower legs, chest, upper arms, cardio, shoulders, lower arms, neck) plus a finer `target` — [RapidAPI ExerciseDB](https://rapidapi.com/justin-WFnsXH_t6/api/exercisedb), [hasaneyldrm README](https://raw.githubusercontent.com/hasaneyldrm/exercises-dataset/main/README.md)
- rthepen's 29-slug taxonomy splits deltoids (anterior/lateral/posterior), glutes (maximus/medius), abs (rectus/obliques/transverse) and includes rotator_cuff, rhomboids, erector_spinae, tibialis_anterior — [rthepen/workout-database](https://github.com/rthepen/workout-database)
- exercemus explicitly ships a `muscle_groups` "map<string, list<string>> which defines which muscle group corresponds to which muscles" — [exercemus/exercises](https://github.com/exercemus/exercises)

### Inferences
- Recommended crosswalk from each source to the app's 11 body parts (chest, back, shoulders, biceps, triceps, forearms, quads, hamstrings, glutes, calves, abs):
  - free-exercise-db: chest→chest; lats, middle back, lower back, traps→back; shoulders→shoulders; biceps→biceps; triceps→triceps; forearms→forearms; quadriceps→quads; adductors→quads (follows Liftosaur, which files adductor brevis/longus under quadriceps); hamstrings→hamstrings; glutes→glutes; abductors→glutes (Liftosaur files gluteus medius/TFL under glutes); calves→calves; abdominals→abs; neck→unmapped/other.
  - wger: Pectoralis major, Serratus anterior→chest; Latissimus dorsi, Trapezius→back; Anterior deltoid→shoulders; Biceps brachii, Brachialis→biceps; Triceps brachii→triceps; Quadriceps femoris→quads; Biceps femoris→hamstrings; Gluteus maximus→glutes; Gastrocnemius, Soleus→calves; Rectus abdominis, Obliquus externus abdominis→abs. wger has no forearm, lower-back, lateral/posterior-deltoid muscle, so lateral raises and face pulls map only to "Shoulders".
  - Hevy: lats, upper_back, lower_back, traps→back; abductors→glutes; adductors→quads; cardio, full_body, neck, other→unmapped.
- Keep a three-level hierarchy (fine muscle → muscle group → body part) so the app can later show Hevy-style 15–20 groups without re-tagging exercises; store the Liftosaur mapping as the canonical fine-to-coarse table because it is the only one published verbatim as code with an inverse map.
- "Traps" is the main ambiguity across sources (Hevy separates it; Liftosaur puts trapezius under back; wger leaves its English name empty). Choose back for rows/shrugs and document it.

### Gaps
- No peer-reviewed or "official" mapping table exists; the Liftosaur map is a developer's convention, not an anatomical standard.
- exercemus's actual `muscle_groups` map contents could not be read (file truncated).

## Key Question 3: How do Hevy, Strong, Boostcamp and Alpha Progression categorise exercises and exercise types, and how do they record which muscles a set counts toward?

### Takeaway
Hevy is the best-documented model: 8 exercise types, one primary + many secondary muscle groups per exercise, an equipment category, and per-set types normal/warmup/dropset/failure; Strong documents only that it supports "multiple Exercise Types, including Assisted Bodyweight and Duration" and a "Count Dumbbells Twice" volume option; Alpha Progression documents 8 set-logging formats plus a 0–100% "bodyweight involvement" factor and main/auxiliary muscles; Boostcamp exposes a per-muscle weekly volume heatmap (Pro) but does not publish its taxonomy.

### Cited Findings

## Key Question 4: What naming conventions does Strong's CSV export use, and is there a published list or community mapping to another taxonomy?

### Takeaway
Strong exports one row per set with 12 columns and names exercises as "Movement (Equipment)" — e.g. "Bench Press (Barbell)", "Incline Bench Press (Barbell)", "Hip Adductor (Machine)", "Hip Thrust (Bodyweight)", "Face Pull (Cable)" — with Set Order carrying W/D/F markers and "Rest Timer" pseudo-rows; there is no official exercise list, but strong2hevy (YAML map to Hevy template IDs), gym-progress (exercise→muscles JS map) and StrongToGymRun (Python dict) are community mappings you can seed from.

### Cited Findings
- Real export header (iOS user, 2020–2021): `Date,Workout Name,Duration,Exercise Name,Set Order,Weight,Reps,Distance,Seconds,Notes,Workout Notes,RPE`; example rows `2020-12-30 18:51:52,"Evening Workout",2h 38m,"Snatch (Barbell)",1,40.0,3,0,0,"","",` and a cardio row `2021-05-13 12:00:00,"Evening Workout",5m,"Swimming",1,0,0,1.0,30,"","",`; distinct names include "Snatch (Barbell)", "Front Squat (Barbell)", "Overhead Press (Barbell)", "Power Clean" (no suffix), "Bench Press (Barbell)", "Strict Military Press (Barbell)", "Swimming" — [StrongAppAnalytics strong.csv](https://raw.githubusercontent.com/AlexandrosKyriakakis/StrongAppAnalytics/main/Data/strong.csv)
- Naming pattern "Exercise Name (Equipment Type)" with examples "Squat (Barbell)", "Lunge (Dumbbell)", "Hip Adductor (Machine)", "Hip Thrust (Bodyweight)", "Incline Bench Press (Barbell)", "Face Pull (Cable)"; dates like `2024-11-02` — [AJ's blog: parsing Strong data](https://blog.ayjc.net/posts/strong-app-parsing/)
- Taper's column list: Date ("Workout start time, like 2021-07-24 10:37:18"), Workout Name, Duration, Exercise Name, Set Order ("The set's position within that exercise"), Weight, Reps, Distance, Seconds, RPE; "Values are in whatever unit your Strong app is set to log in" with no unit column — [Taper: export Strong data](https://thetaperapp.com/articles/how-to-export-strong-data/)
- Set Order letter markers: "W (warm-up), D (drop set), or F (failure)"; "Rows Strong labels Rest Timer are skipped rather than imported as empty timed sets"; Strong's CSV "stores the weight number but not the unit"; Gript matches names on a "Match Exercises" screen and lets "unmatched movements be created as custom exercises"; only completed workouts export, not templates — [Gript: import from Strong](https://griptapp.com/help/import-from-strong)
- RepStack: "Set Order is numeric and resets cleanly per exercise"; "Check whether weights are kg or lb, especially if you used mixed units"; "If weights use decimal commas, convert them to decimal points before importing" — [RepStack Strong CSV import](https://rep-stack.com/import/strong-csv/)
- Strong: "exported files cannot be imported back into Strong"; export via Settings → "Export Strong Data" (iOS) — [Strong help: export](https://help.strongapp.io/article/235-export-workout-data)
- Hevy officially imports Strong CSVs: "Hevy only allows you to import CSVs from the Strong app, and the file must be in English"; path Profile > Settings > Export & Import Data > Import Data > Import Strong CSV; only one import allowed (revertable) — [Hevy help: import Strong CSV](https://help.hevyapp.com/hc/en-us/articles/38001424401943-How-to-Import-Strong-App-CSV-Files-and-Export-Your-Data-in-Hevy) (page returned 403; details from search snippet)
- strong2hevy (criccomini): "Exact normalized title match -> auto-resolved to a Hevy template"; YAML map entries `strong_name: Bench Press (Barbell) / action: use-template / template_id: b459cba5-...`; actions `use-template`, `create-custom`, `skip`; "Strong `Set Order = W` becomes a Hevy `warmup` set. Numeric Strong set orders become normal sets."; "Weight is converted to `weight_kg`" — [strong2hevy](https://github.com/criccomini/strong2hevy)
- gym-progress (timscheffer96): `exercise-muscles.js` "maps each exercise name in the supplied export to its primary and secondary muscle groups"; "Hevy rows are normalized to the same internal fields as Strong rows"; "Common equivalent exercise names are canonicalized so the existing muscle mappings remain useful"; "Explicit Hevy warm-up sets are excluded from hard-set volume" — [gym-progress](https://github.com/timscheffer96/gym-progress)
- StrongToGymRun keeps a name dictionary in `static.py` ("Simply open the file `static.py` and add your exercise to the dictionary") with a separate list for bodyweight exercises — [StrongToGymRun](https://github.com/AchrafYndz/StrongToGymRun)
- heart-api issue #39 frames the problem: "Exercise-name mapping — the actual hard part: 'Bench Press (Barbell)' → catalog exercise ID; unmatched names → auto-created custom exercises"; proposes that "a mapping dictionary is itself reference content: versioned, server-served, improvable as real-world imports surface misses" — [heart-api #39](https://github.com/kit-g/heart-api/issues/39)
- Hevy's own template titles use the same convention (e.g. "Squat (Barbell)") — [life-platform issue #4108](https://github.com/averagejoematt/life-platform/issues/4108), [strong2hevy](https://github.com/criccomini/strong2hevy)

### Inferences
- Parser rule: split `Exercise Name` on the last " (" to get `base_name` and `equipment_token` ∈ {Barbell, Dumbbell, Machine, Cable, Bodyweight, ...}; names without a suffix (e.g. "Power Clean", "Swimming", custom names) fall back to fuzzy/alias matching. Map the equipment token to the app's equipment enum, then resolve `base_name` against an alias table that includes free-exercise-db names ("Incline Dumbbell Press" ↔ "Incline Bench Press (Dumbbell)"; "Seated Cable Rows" ↔ "Seated Row (Cable)"; "Dips - Chest Version" ↔ "Chest Dip"; "Cable One Arm Tricep Extension" ↔ "Triceps Extension (Cable)" one-arm variant).
- Treat Set Order `W` as warmup (exclude from hard-set counts), `D` as dropset, `F` as failure, skip "Rest Timer" rows, and keep RPE. Weight is per-dumbbell as entered; whether to double for volume must be a per-exercise flag (mirroring Strong's "Count Dumbbells Twice").
- Because Hevy uses the identical "(Barbell)" naming style, a single alias table serves both Strong and Hevy imports.

### Gaps
- No complete, published list of Strong's ~200 built-in exercise names was found; the sample CSV covers only 18 names. The strong2hevy repo may contain a fuller example map in its files but the README shows only three names.
- Whether Strong's CSV `Weight` for dumbbell exercises is ever pre-doubled (when "Count Dumbbells Twice" is on) is undocumented.
- Whether Strong exports "Note" pseudo-rows (in addition to "Rest Timer") was not confirmed by any importer documentation.

## Key Question 5: How do datasets represent machine exercises and settings, and does any dataset/app store per-machine adjustable settings?

### Takeaway
Every dataset flattens machines into one or two equipment tokens ("machine", "leverageMachine", "Smith Machine", "cable"); only Alpha Progression enumerates specific machines (butterfly, leg press, chest press, Smith, "All other machines"). No dataset stores adjustable settings; among apps, Hevy's routine-level exercise notes and niche apps such as My GymMachine Binder (per-machine cards with seat height and handle position) are the only documented mechanisms, so the app must model settings itself.

### Cited Findings
- free-exercise-db equipment enum has a single `"machine"` plus `"cable"`; its machine exercises are tagged e.g. "Leg Press" equipment "machine", "Machine Bench Press" equipment "machine", "Seated Cable Rows" equipment "cable", "Cable One Arm Tricep Extension" equipment "cable" — [schema.json](https://raw.githubusercontent.com/yuhonas/free-exercise-db/main/schema.json), [Leg_Press.json](https://raw.githubusercontent.com/yuhonas/free-exercise-db/main/exercises/Leg_Press.json), [Machine_Bench_Press.json](https://raw.githubusercontent.com/yuhonas/free-exercise-db/main/exercises/Machine_Bench_Press.json)
- wger has "Cable machine" but no generic "machine" equipment value at all — [wger equipment](https://wger.de/api/v2/equipment/)
- Liftosaur equipment enum: "barbell", "cable", "dumbbell", "smith", "band", "kettlebell", "bodyweight", "leverageMachine", "medicineball", "ezbar", "trapbar"; each exercise has one `defaultEquipment` (e.g. legPress "leverageMachine", seatedRow "cable") and equipment is a separate field on `IExerciseType {id, equipment}` rather than part of the id — [liftosaur types.ts](https://raw.githubusercontent.com/astashov/liftosaur/master/src/types.ts), [liftosaur exercise.ts](https://raw.githubusercontent.com/astashov/liftosaur/master/src/models/exercise.ts)
- ExerciseDB-style equipment: "Leverage Machine", "Smith Machine", "Cable" — [hasaneyldrm README](https://raw.githubusercontent.com/hasaneyldrm/exercises-dataset/main/README.md); Hevy API equipment: "machine" (plus "smith_machine" in one summary) — [hevy-mcp openapi-spec.json](https://raw.githubusercontent.com/chrisdoc/hevy-mcp/main/openapi-spec.json), [skills.lc Hevy API skill](https://skills.lc/sergiocarracedo/skills/sergiocarracedo-skills-skills-hevy-api-skill-md); workout.cool: MACHINE, SMITH_MACHINE, CABLE — [workout-cool schema.prisma](https://raw.githubusercontent.com/Snouzy/workout-cool/main/prisma/schema.prisma)
- Alpha Progression's equipment list names concrete machines ("Butterfly, Reverse butterfly, Leg extension, Leg curl, Leg press, Chest press, Smith machine, All other machines" and cable stations "Lat pulldown, Cable, Crossover cable, Row cable") — [Alpha Progression guide](https://alphaprogression.com/en/blog/alpha-progression-guide)
- Hevy notes: "Routine Notes" attach to an exercise in a routine and "appear with their respective exercises each time you use the routine"; "Workout Notes" are per-session; examples given: "Elevate the front foot on three weight plates." — [Hevy help: exercise notes](https://help.hevyapp.com/hc/en-us/articles/34463684392983-How-do-the-exercise-notes-routine-and-workout-notes-work), [Hevy exercise notes feature](https://www.hevyapp.com/features/exercise-notes/)
- Strong's CSV carries free-text `Notes` (per exercise) and `Workout Notes` columns — [StrongAppAnalytics strong.csv](https://raw.githubusercontent.com/AlexandrosKyriakakis/StrongAppAnalytics/main/Data/strong.csv)
- "My GymMachine Binder": "each machine gets its own card where you can record seat height, handle position, weight preference, repetitions, and any special adjustments"; cards can be grouped "by muscle group or gym area" — [My GymMachine Binder (App Store)](https://apps.apple.com/iq/app/my-gymmachine-binder/id6756008950?l=ar); "WerRic" keeps "track of the weight settings for workout machines" — [WerRic (App Store)](https://apps.apple.com/ca/app/werric/id6499362272)
- RepDB is the only dataset with `is_unilateral` and `is_bodyweight` boolean flags per exercise — [RepDB/exercise-dataset](https://github.com/RepDB/exercise-dataset); Liftosaur is the only tracker with a per-set `isUnilateral` flag and `completedRepsLeft` for the second side — [liftosaur types.ts](https://raw.githubusercontent.com/astashov/liftosaur/master/src/types.ts)

### Inferences
- Proposed storage: `gym(id, name)`; `machine(id, gym_id, label, brand/model, photo, exercise_id default)`; `machine_setting(machine_id, key, value, unit/text, updated_at)` with keys like seat_height, back_pad, arm_position, foot_plate, range_limiter; plus `exercise_gym_pref(exercise_id, gym_id, machine_id, notes)` so an exercise like "Chest Press (Machine)" resolves to a concrete machine and its settings at the current gym. Surface the last-used settings inline when the exercise is added to a workout, and version them (append-only) so a change is recorded with the date.
- Keep "settings" separate from the exercise definition: the same exercise is performed on different machines across gyms, and the same machine hosts several exercises.

### Gaps
- No open dataset or open-source tracker examined stores adjustable machine settings; this is a genuine app-side design decision with no reference schema to copy.

## Key Question 6: What do open-source workout apps' data models look like (exercises, templates, workouts, sets, set types) and what licences do they carry?

### Takeaway
wger (AGPL-3.0-or-later) models Routine → Day → Slot → SlotEntry with per-iteration config objects and logs each performed set as a WorkoutLog; Liftosaur (AGPL-3.0) models sets with warmup arrays, AMRAP/RPE flags and unilateral fields on top of a fine-grained muscle model; workout.cool (MIT) uses an attribute (EAV) model for exercises and a set-type enum TIME/WEIGHT/REPS/BODYWEIGHT/NA; FitTrackee (AGPL-3.0) is an outdoor-GPX tracker with no strength model. Hevy's public API (normal/warmup/dropset/failure sets with weight_kg/reps/distance_meters/duration_seconds/rpe) is the de-facto interchange schema targeted by community importers.

## Key Question 7 (synthesis): Recommended body-part taxonomy, data model (exercise → muscle groups → body part) and coverage of common gym exercises

### Takeaway
Seed from free-exercise-db (public domain, images included, covers all eight probe exercises), cross-check names/aliases against wger (912 exercises; "Leg Press", "Hip Thrust", "Lateral Raises", "Chest Press", "Dips" all present by exact English name), store muscles at three levels (Liftosaur-style fine muscle → Hevy-style 20 groups → 11 body parts), give every exercise a Hevy-style exercise type, laterality and load model, and weight primary muscles 1.0 / secondary 0.5 when aggregating sets and volume per body part.

### Inferences
- Body-part taxonomy (11): chest, back, shoulders, biceps, triceps, forearms, quads, hamstrings, glutes, calves, abs. Muscle-group layer (Hevy's 20 minus cardio/full_body/other): abdominals, shoulders, biceps, triceps, forearms, quadriceps, hamstrings, calves, glutes, abductors, adductors, lats, upper_back, traps, lower_back, chest, neck. Fine layer: Liftosaur's 39 muscle strings (optional, for a heat map).
- Schema sketch:
  - `body_part(id, name, sort)`; `muscle_group(id, name, body_part_id)`; `muscle(id, name, muscle_group_id)` (Liftosaur mapping seeds the joins).
  - `exercise(id, canonical_name, base_movement, equipment, exercise_type [weight_reps|bodyweight_reps|weighted_bodyweight|assisted_bodyweight|duration|weight_duration|distance_duration|weight_distance], mechanic, force, laterality [bilateral|unilateral_alternating|unilateral_single], load_model [total|per_hand|added|assistance], bodyweight_factor 0–1, is_custom, source_dataset, source_id, licence)`.
  - `exercise_muscle(exercise_id, muscle_group_id, role [primary|secondary], weight 1.0|0.5)` — weights configurable so rankings can be recomputed.
  - `exercise_alias(exercise_id, alias, source [strong|hevy|free-exercise-db|wger|user])` — seeded from free-exercise-db names, wger English names and the "Name (Equipment)" forms used by Strong/Hevy.
  - `workout(id, started_at, ended_at, name, notes, gym_id)`; `workout_exercise(id, workout_id, exercise_id, order, superset_id, notes, machine_id)`; `set(id, workout_exercise_id, index, set_type [normal|warmup|dropset|failure], weight_kg, reps, duration_s, distance_m, rpe, rir, side [both|left|right], completed)`.
  - `template`/`template_exercise`/`template_set` mirror workout tables (Jim's "structure only" approach) plus target rep ranges.
  - Machine tables from KQ5.
- Effective load per set for rankings: weight_reps → weight_kg; per_hand dumbbells → weight_kg × 2 when comparing to barbell volume (mirror Strong's toggle); weighted_bodyweight → bodyweight_kg × bodyweight_factor + added_kg; assisted_bodyweight → bodyweight_kg × bodyweight_factor − assistance_kg; unilateral_single sets logged per side count reps per side. Per body part: hard sets = Σ non-warmup sets × muscle weight; volume = Σ effective_load × reps × muscle weight; rankings use rolling-window e1RM on the best set per exercise, roll-up = max over exercises in the body part.
- Strong reconciliation pipeline: (1) parse "(Equipment)" suffix; (2) exact match on alias table; (3) fallback token match on base_movement + equipment; (4) manual review list for leftovers, persisted as new aliases (strong2hevy/heart-api pattern); (5) map Set Order W/D/F → set_type, skip "Rest Timer"; (6) ask unit once per import (no unit column).

### Gaps
- Only eight probe exercises were checked in free-exercise-db and five in wger; a full-catalogue coverage audit (e.g. every Strong built-in name) was not possible without Strong's list.
- The 0.5 secondary weight and bodyweight factors are proposals; no app publishes its exact formula for secondary-muscle credit.
