# Workout-tracker UX patterns: templates, live workout, rest timers, notes, progress, Strong export

Scope note: research current as of 2026-09-26. Reddit is blocked for this crawler (`reddit.com` refused), so user sentiment comes from App Store / Google Play listings, the JustUseApp review aggregator, third-party reviews (RepReturn, Garage Gym Reviews, Setgraph, PonteFuerte, dr-muscle, The Nerdy Student) and open-source issue trackers that cite user churn. Several Hevy help-centre pages return HTTP 403 to fetchers; I read them through Zendesk's public JSON API (`/api/v2/help_center/en-us/articles/<id>.json`) and cite the human URLs.

## Q1. Templates: how Strong and Hevy model a template, what happens on start, template vs today's workout, per-exercise rest times

### Takeaway
Both apps model a template ("Template" in Strong, "Routine" in Hevy) as an ordered list of exercises, each with target sets (weight × reps or rep range), optional set tags, optional notes, superset grouping and — in Hevy — an explicit per-exercise rest duration saved in the routine. Starting a template clones it into a live workout; edits during the workout never touch the template until an end-of-workout prompt asks whether to update it (Strong offers four options, Hevy a binary "apply changes / keep original"). Strong's per-exercise rest time is a property of the exercise (shared across templates), whereas Hevy stores it per exercise-in-routine.

### Cited Findings
**Strong — template model and limits**
- Templates are "structured workout blueprints containing exercises and sets"; in a template "Sets cannot be completed" and "Rest Timer is not available when modifying a Template". Templates are created from the "+ Template" button on the Start Workout tab, inside folders, or from History via More (...) > "Save as Template"; free tier: "You can create up to 3 Workout Templates"; Strong ships "some default templates as examples" — [Strong Help: What is a Template](https://help.strongapp.io/article/105-about-templates)
- Third-party reviews describe the same cap as "Maximum of 3 custom routines" (RepReturn, 2026-03-10) — [RepReturn Strong review](https://repreturn.com/strong-app-review/); and "3 active routines" (PonteFuerte, updated 2026-09-17) — [PonteFuerte Hevy vs Strong](https://www.pontefuerteai.com/blog/hevy-vs-strong-vs-pontefuerteai-workout-app-comparison)
- Template category articles: organise templates (folders), edit/delete template, share template, update template on finish, "Templates keep disappearing (iOS)" — [Strong Help category: Using Workout Templates](https://help.strongapp.io/category/150-workoutsroutines)
- Strong's home screen "launches showing saved templates organized in folders"; users "quickly launch your workout" from a template "with preset weights and sets, or start an empty workout" (2021 review, still matches current help docs) — [The Nerdy Student, 2021](https://www.thenerdystudent.com/2021/08/strong-review/)
- Notes are part of the template: "An Exercise Note in a Template will be duplicated each time you perform that workout"; likewise "a workout note in a Template will be duplicated each time you perform that workout" — [Strong Help: About Notes](https://help.strongapp.io/article/134-about-notes)
- Supersets: "A Superset is a way to group exercises and perform them in parallel"; grouped exercises show "a vertical line on the left side"; the Next button selects "the next set from the appropriate exercise" (A1, B1, A2, B2…). iPhone: multi-select exercises in Add Exercise then tap the Superset button; the article does not state whether supersets persist in templates — [Strong Help: Supersets / Circuits](https://help.strongapp.io/article/98-supersets-and-circuits)

**Strong — finishing a workout started from a template**
- On finishing a modified template workout, the prompt offers exactly: "Update Template" (replaces the whole template with the workout; "Displays in red if destructive (e.g., exercises removed)"), "Update Values Only" (updates the template's weights and reps), "Update Template and Values" (replaces the template "including any changes made to values within sets"), and "Keep Original Template". The prompt can be disabled in Strong Settings; the docs say the process will be adjusted "to reduce confusion" — [Strong Help: Update a Template when completing a Workout](https://help.strongapp.io/article/177-update-template)
- Bug reported by a reviewer: "Not completing all exercises in a routine on watch deletes them from the routine after save" — [JustUseApp Strong reviews](https://justuseapp.com/en/app/464254577/strong-workout-tracker-gym-log/reviews)
- Known iOS sync bug (pre-6.0): templates disappear; "if you log out and log in again, all the templates should return"; cloud sync was rebuilt for 6.0 — [Strong Help: Templates keep disappearing (iOS)](https://help.strongapp.io/article/253-templates-disappearing)

**Strong — where per-exercise rest time lives**
- "The default Rest Timer for all exercises is 2:00 and triggers immediately after a set is completed"; you can "change the default timer duration for any exercise via the More (...) Menu", with separate settings for "Warm-up Sets and Working (Regular) Sets" — [Strong Help: About Rest Timer](https://help.strongapp.io/article/231-rest-timer)
- A now-deleted help article (HTTP 404 on fetch; text survives only in search-engine snippets) described the flow as: tap the [...] button next to the exercise, select "Auto Rest Timer", turn on the "Enabled" switch and pick a time — [Strong Help: How do I set the rest timer (404)](https://help.strongapp.io/article/161-how-do-i-set-the-rest-timer)
- User complaint that shows the setting is per exercise, not per template: "if you use that same exercise in a different workout...it sets the rest time to the time you used in the last workout you used the exercise in which is a little bit of a pain" — [JustUseApp Strong reviews](https://justuseapp.com/en/app/464254577/strong-workout-tracker-gym-log/reviews)
- Strong's v6.2.4+ CSV export contains "a `Rest Timer` row per exercise" inside each workout — [Kinoku import-format page](https://kinoku.app/import-format); importers "ignore" these rows — [Avex PR #202](https://github.com/antho976/Avex/pull/202), [Gript import guide](https://griptapp.com/help/import-from-strong)

**Hevy — routine model**
- "A routine is a plan for a workout... a workout template you can reuse unlimited times"; edit via three dots > "Edit Routine" to change "exercises, sets, rep targets, and rest periods"; a workout is the live log — [Hevy Help: Workouts vs Routines](https://help.hevyapp.com/hc/en-us/articles/33703513582871-Workouts-vs-Routines-in-Hevy-What-They-Mean-and-How-to-Use-Them)
- Routine contents: exercises (supersets/circuits), sets with "specific rep counts or rep ranges", weight targets, rest duration per exercise, notes with clickable links, set types; folders can be reordered/renamed/deleted; "Start Routine" from the Workout tab; during the workout you can "modify exercises, sets, rest timers, and notes in real-time without affecting the saved template"; at the end "Hevy asks whether you want the current changes to apply to your saved routine or keep it in its original state" — [Hevy: Gym Routines](https://www.hevyapp.com/features/gym-routines/)
- Set programming: weight per set under KG/LBS columns; REPS accepts a single target or a range "for example, 6 to 8"; duration exercises use TIME; RPE column toggled in Profile > Settings > Workouts > RPE Tracking; supersets via three dots > "+ Add To Superset"; no cap on exercises or sets — [Hevy: Exercise Programming Options](https://www.hevyapp.com/features/exercise-programming-options/)
- Rest timer is saved in the routine: "Rest periods are saved within routines and remain persistent across workouts, though users can override them during individual sessions" — [Hevy: Workout Rest Timer](https://www.hevyapp.com/features/workout-rest-timer/)
- Default Rest Timer (Profile > Settings > Workouts) is applied "to every exercise added to an active workout or routine" and "does not apply retroactively to existing routines"; per-exercise: "Tap 'Rest Timer' below the exercise name", scroll to a duration — [Hevy Help: Rest Timer & Default Rest Timer](https://help.hevyapp.com/hc/en-us/articles/35385404949143-Rest-Timer-Default-Rest-Timer-How-to-Add-Adjust-Volume-and-Sound)
- Free tier includes "unlimited routines" — [PonteFuerte](https://www.pontefuerteai.com/blog/hevy-vs-strong-vs-pontefuerteai-workout-app-comparison); App Store description lists "Unlimited routine creation" — [Hevy App Store](https://apps.apple.com/us/app/hevy-workout-tracker-gym-log/id1458862350)
- User complaint contradicting the marketing page's end-of-workout prompt: "no option to save & update routine if you changed an exercise mid workout" and no prompt "distinguishing between saving values alone versus updating routine" — [JustUseApp Hevy reviews](https://justuseapp.com/en/app/1458862350/hevy-workout-tracker-gym-log/reviews)
- Hevy 3.1.11 (2026-08-28) added "split options (Full Body, Upper/Lower, Push Pull Legs)" as routine starting points — [Hevy App Store](https://apps.apple.com/us/app/hevy-workout-tracker-gym-log/id1458862350)

**Other apps (brief)**
- Boostcamp: a 3-year user praises "I go into the gym and just click start on whatever day is next in your routine" — [Boostcamp App Store](https://apps.apple.com/us/app/boostcamp-workout-programs/id1529354455); mid-workout "exercise alternatives that carry your weights to substitutes" — [Boostcamp features](https://www.boostcamp.app/features)
- Liftoff: generator "builds sessions and multi-week programs... Save them as presets, tweak them, or just hit start" — [Liftoff gamified tracker page](https://liftoffrank.com/gamified-workout-tracker)
- RepCount: "save a routine so your exercises are ready next time"; unlimited routines free — [RepCount site](https://www.repcountapp.com/)
- Gymverse complaint: scheduled workouts are "ONLY available on that day" (developer says fixed) — [Gymverse App Store](https://apps.apple.com/us/app/gymverse-gym-workout-planner/id1048454034)

### Inferences
- A personal app should keep Strong's four-way finish prompt semantics but simplify: (a) "update targets from today" (values only) and (b) "replace structure" are the two operations users actually distinguish; Strong's docs admit the current wording confuses people.
- Store rest time on the template-exercise row (Hevy model) but seed it from an exercise-level default (Strong model) — this satisfies both the "different rest for the same exercise in different days" case and the complaint quoted above.
- Because Strong's newer export writes a `Rest Timer` row per exercise, the importer can recover the user's existing per-exercise rest settings from their own history (see Q6).

### Gaps
- Strong's help centre does not state whether supersets or per-exercise rest settings are persisted inside a template versus on the exercise globally; only the user review and the export format evidence the per-exercise (global) model.
- Hevy's per-exercise rest-time UI range is documented (5 s–5 min) but the picker's step size is not.

## Q2. Live workout screen: set rows, completing a set, auto-start, previous values, set types; per-exercise and per-set-type rest times

### Takeaway
The de-facto standard (Strong, Hevy, RepCount, Boostcamp) is a per-exercise table with columns Set | Previous | kg | Reps | ✓; tapping ✓ marks the set done (green row), auto-starts that exercise's rest timer, and fires a PR badge if applicable. Tapping the set number opens the set-type menu (Warm-up / Drop / Failure). Only Strong documents distinct rest durations for warm-up vs working sets; Hevy has one duration per exercise (and suppresses the timer between consecutive drop sets); Alpha Progression sets durations by exercise type; Fitbod generates them per exercise per session.

### Cited Findings
**Strong**
- Workflow: "A Workout consists of a list of Exercises, which you will perform in order"; enter "the weight and reps performed, and complete it by hitting the checkbox"; "Add Set" button; "Swipe to Delete"; "Finish" top right — [Strong Help: My first workout](https://help.strongapp.io/article/229-my-first-workout)
- UI spec (third-party design blueprint): "the Set/Previous/kg/Reps grid" with "tabular-figure cells", "set-done green fill", "amber PR flag", a "slim rest-timer progress bar", "Finish button" in the header, "Inter type tuned for arm's-length reading", "single-accent palette with neutral-grey surfaces" — [Spectr: Strong UI blueprint](https://www.spectr.to/gallery/strong)
- "The app pre-fills your last set data, so adding 5 pounds or squeezing out an extra rep takes seconds" — [Setgraph: Strong alternatives](https://setgraph.app/articles/best-strong-app-alternatives-(2025)); users: "it remembers the sets from the previous workout", "reminds you what you did last time" — [strong.app/love](https://www.strong.app/love)
- Logging cost: "three taps" to log a set once in a session — [RepReturn Strong review](https://repreturn.com/strong-app-review/); counter-claim that Strong "requires multiple taps for basic logging tasks" — [Setgraph](https://setgraph.app/articles/best-strong-app-alternatives-(2025))
- Set tags: "tap on the Set Number (e.g. 1,2,3) in the 'Set' column to bring up this menu"; tap the tag again to revert. Warm-up sets "will not be included in charts or metrics"; Drop Sets = "a series of sets performed without resting"; Failure = a set with an additional failed rep (5 reps tagged Failure means a 6th rep failed; a failed 1RM attempt is logged as 0 reps + Failure); PRO can bulk-add warm-ups via the Warm-up Calculator — [Strong Help: Set tags](https://help.strongapp.io/article/166-set-tags)
- A configurable "focus metric" in the top right shows total volume, volume increase, total reps or weight-per-reps during the workout — [The Nerdy Student, 2021](https://www.thenerdystudent.com/2021/08/strong-review/); "About Focus Metric" is a current help article — [Strong Help category: Record a Workout](https://help.strongapp.io/category/165-logging-a-workout)
- Rest timer: default 2:00 for all exercises, auto-triggers on set completion, shown "in the top left corner of the workout screen"; tap to go full screen to "modify the duration of the timer, or end the current timer immediately by hitting Skip"; separate durations for "Warm-up Sets and Working (Regular) Sets"; manual start "by hitting the timer button directly"; Settings > Rest Timer for sound and behaviour — [Strong Help: About Rest Timer](https://help.strongapp.io/article/231-rest-timer)
- Supersets "with proper rest timer logic"; plate calculator; RPE logging — [RepReturn Strong review](https://repreturn.com/strong-app-review/)

**Hevy**
- Set row: set number, "Previous" values, weight (kg/lbs), reps or duration, completion checkbox; "tap the number next to a set to change it from normal...to warm-up, drop set, or a set to failure"; "+ Add Set"; swipe left for red Delete; PR badges shown live; completed-set count at the top — [Hevy: Track Workouts](https://www.hevyapp.com/features/track-workouts/)
- Set types: Warm Up / Normal / Failure / Drop; drop sets show "a blue D symbol on the left side"; "Rest timer does NOT activate between consecutive drop sets"; other types run the timer normally — [Hevy: Workout Set Types](https://www.hevyapp.com/features/workout-set-types/)
- Rest timer: "You can set a different rest period for each activity in a workout, ranging from five seconds to five minutes"; "-15 and +15 buttons"; auto-starts "once you mark a set as completed"; can be set to "off" per exercise — [Hevy: Workout Rest Timer](https://www.hevyapp.com/features/workout-rest-timer/); the docs do not mention warm-up-specific durations, and PonteFuerte states Hevy has "No differentiation between warmup and working sets" — [PonteFuerte](https://www.pontefuerteai.com/blog/hevy-vs-strong-vs-pontefuerteai-workout-app-comparison)
- The 12 workout settings include: Sounds (timer volume off/low/normal/high, set-completion sound, PR sound), Default Rest Timer, Previous Workout Values, Warm-up Calculator, Warm Up Sets (count toward stats or not), Keep Awake During Workout, Plate Calculator, RPE Tracking, Smart Superset Scrolling (auto-advance to the paired exercise on set completion), Inline Timer (stopwatch for timed sets), Live Personal Record Notification, Units (global or per exercise) — [Hevy: Workout Settings](https://www.hevyapp.com/features/workout-settings/)
- "Previous workout values" setting (Settings > Workouts): "Any workout" = last time you did the exercise anywhere; "Same Routine" = last time within this routine; it "only affects this informational column" — [Hevy Help: Previous Workout Values vs Routine Values](https://help.hevyapp.com/hc/en-us/articles/34105442929943-Previous-Workout-Values-Vs-Routine-Values-How-to-Adjust-in-Settings)
- Hevy "auto-fills your previous weights and reps"; logging speed rated 9.5/10 (RepReturn, 2026-03-07) — [RepReturn Hevy review](https://repreturn.com/hevy-app-review/)
- 3.1.10 (2026-08-20): "Redesigned Set Row UI with RPE color scale; Progressive Overload for reps-only exercises" — [Hevy App Store](https://apps.apple.com/us/app/hevy-workout-tracker-gym-log/id1458862350)
- Three sounds with independent volumes: "the rest timer/timer, the check set sound and the personal record alert... Only the timer has multiple options for the sound" — [Hevy Help: Rest Timer](https://help.hevyapp.com/hc/en-us/articles/35385404949143-Rest-Timer-Default-Rest-Timer-How-to-Add-Adjust-Volume-and-Sound)

**Alpha Progression**
- Logging: weight and reps, optional RIR with "half-values, e.g. 1.5 RIR"; "a convenient weight picker suggesting likely values plus manual keyboard input"; "Your previous sets and notes remain visible"; set types: warm-up, working, dropset; rest timer "starts automatically as soon as you complete a set", "custom durations for different exercise types, such as longer rests for large compound exercises and shorter rests for smaller isolation exercises", alarm at zero — [Alpha Progression Guide](https://alphaprogression.com/en/blog/alpha-progression-guide)
- Recommendation per set "based on your performance in previous workouts, what you have already done during the current workout, and what is planned for the current set"; respects gym increments ("A theoretically optimal recommendation of 31.7 kg is not useful if your machine jumps directly from 30 to 35 kg") — [Alpha Progression Guide](https://alphaprogression.com/en/blog/alpha-progression-guide); reviewer: tracks 10RM rather than 1RM (Fitness Drum, 2025-12-12) — [Fitness Drum review](https://fitnessdrum.com/alpha-progression-app-review/); App Store reviewer: recommendations adapt "set to set because fatigue is real" — [Alpha App Store](https://apps.apple.com/us/app/gym-workout-alpha-progression/id1462277793)

**Boostcamp**
- Shows "exercise, target sets/reps, and last logged weight"; "The timer auto-starts"; RPE (5–10) and RIR "on any set"; plate calculator; "loads next session's weights" after prescribed reps are hit; warm-up templates; drop sets "to any working set" — [Boostcamp Workout Tracker page](https://www.boostcamp.app/workout-tracker); v265 (2026-09-05): "Rebuilt rest timer with improved workout page highlighting and collapsible finished exercises" — [Boostcamp App Store](https://apps.apple.com/us/app/boostcamp-workout-programs/id1529354455)

**Fitbod**
- Rest timers "are only for a singular exercise for a singular workout and are generated depending on the difficulty of the lift"; adjustable via "(time) REST" pre-workout or during; Settings > Workout Settings > rest timer notifications so you can "close the app, browse other apps or lock your phone and still be notified" — [Fitbod Help: Rest Timer (search snippet; page returns 403)](https://fitbod.zendesk.com/hc/en-us/articles/360006340194-Rest-Timer)

**RepCount / Gymverse / Liftoff / JEFIT**
- RepCount: workout screen shows "weight, reps and notes for logged sets, with an Add Set button"; "prefills today's workouts with weights from the last workout"; rest timer "can start automatically when you complete a set"; supersets/drop sets are Premium — [RepCount site](https://www.repcountapp.com/), [RepCount App Store](https://apps.apple.com/us/app/repcount-gym-workout-log/id594982044)
- Gymverse "keeps current set, target range, redo action, bulk logging, and next exercise visible simultaneously" and "supports quick corrections without resetting rest timer"; JEFIT keeps "active set table visible above configurable 59-second rest timer" with "±15 seconds, skip, pause, and preset options" — [ScreensDesign: workout tracker design examples](https://screensdesign.com/articles/workout-tracker-app-design-examples/)
- Liftoff: "change the default rest timer for exercises" from "the rest timer on the top left of the tracker sheet" — [Liftoff FAQ](https://liftoffrank.com/en/faq)
- Stated best practices: "Target, previous, pre-filled, and confirmed values are visually distinct"; rest timers should "survive backgrounding and remain attached to the correct set"; substitutions should "record the original and replacement" — [ScreensDesign](https://screensdesign.com/articles/workout-tracker-app-design-examples/)

### Inferences
- Model per-set-type rest durations (warm-up vs working; zero for drop sets) at the template-exercise level — that combines the only two documented refinements (Strong's warm-up/working split; Hevy's no-timer-between-drop-sets) and both are cited pain points for Hevy users.
- The Previous column should be sourced with a "same template vs any workout" switch (Hevy's setting) — for a PPL user who does the same exercise on different days at different rep targets, "same template" is the more useful default.
- Visually distinguishing target (from template), previous (history), pre-filled (proposed) and confirmed (checked) values is the one design rule repeated across sources.

### Gaps
- No source documents the tap-to-copy behaviour of the Previous cell in Strong or Hevy explicitly (only "pre-fills" claims); the exact fill logic (copy previous vs copy template target) is not published.
- Hevy's drop-set timer suppression is documented; whether Strong suppresses the timer within drop sets is not.

## Q3. Rest timer on iPhone when locked/backgrounded: notifications, Live Activities / Dynamic Island, Apple Watch; known failures

### Takeaway
Hevy (free tier), Alpha Progression, Liftoff, LiftVault, Setgraph and Musklr show the running rest timer as an iOS Live Activity on the Lock Screen / Dynamic Island, with ±15 s and skip controls (Hevy also lets you mark the next set complete from the widget); Strong added Live Activity/Dynamic Island rest timers only in v6.5.0 (App Store: 12 Aug, year not shown; the lack of it is cited as a churn reason). All apps back the countdown with a local notification at T-0; the documented failure modes are notifications not sounding outside the app, watch–phone sync dropouts and timers resetting on sync.

### Cited Findings
**Hevy**
- Live Activity shows current exercise and set, next activity, prescribed weight/reps, elapsed duration, rest timer and "previous workout performance data"; from the Lock Screen / Dynamic Island you can "Mark set as completed", adjust the timer in 15-second increments, or skip it; it is available on the free plan and appears automatically when a workout starts; a notification fires when the timer reaches zero. Required iOS setup: Settings > Face ID & Passcode > "Allow Access When Locked" > Live Activities on, plus Hevy notification permissions; Android uses an ongoing notification — [Hevy: Live Activity](https://www.hevyapp.com/features/live-activity/), [Hevy Help: Live Activity](https://help.hevyapp.com/hc/en-us/articles/35649846517399-How-to-Use-Hevy-s-Live-Activity-on-iOS-and-Android)
- "Once it counts down to zero, Hevy notifies you it's time for the next set" — [Hevy: Workout Rest Timer](https://www.hevyapp.com/features/workout-rest-timer/)
- Complaints: "timer doesn't sound if you're not in Hevy"; "There are times it doesn't work but mostly it does"; a watch user wants the "timer still active" while navigating the routine on Apple Watch; praise: the app "will play a tone to tell you rest is over" and "Apple watch synching is much more seamless" — [JustUseApp Hevy reviews](https://justuseapp.com/en/app/1458862350/hevy-workout-tracker-gym-log/reviews); "Apple Watch sync reliability issues" listed as a Hevy complaint — [PonteFuerte](https://www.pontefuerteai.com/blog/hevy-vs-strong-vs-pontefuerteai-workout-app-comparison)

**Strong**
- App Store version history: "Version 6.5.0 (Aug 12): New: Live Activity and Dynamic Island support for rest timers"; 6.1.0 (Jun 16) fixed timer and keyboard issues; a reviewer thanks the team for "Live Activity and Dynamic Island support" — [Strong App Store](https://apps.apple.com/us/app/strong-workout-tracker-gym-log/id464254577). (A search-engine summary attributed the feature to 6.0.4 on 2025-06-04, but the store's own 6.0.4 entry lists only calendar/widget fixes, so treat the 6.5.0 entry as authoritative.)
- Before that release, an open-source competitor's tracker recorded the missing Lock Screen timer as a churn driver: mentioned "12+ times in community discussions", "one lifetime subscriber switched to competitor Hevy", "Live Activities need a native iOS widget extension" — [heart-of-yours issue #133](https://github.com/kit-g/heart-of-yours/issues/133)
- Apple Watch: "once a timer is active, you can edit the duration of a running timer with the Digital Crown"; timer can be disabled on the watch; unit changes must be made on iPhone; rest-timer duration changes on iPhone sync to the watch; a "significant redesign" of the watch app is planned — [Strong Help: Apple Watch](https://help.strongapp.io/article/224-workout-on-apple-watch)
- Reliability complaints: after the Apple Watch integration update, "inconsistent rest timers, sync problems where sets uncheck randomly, entire workouts going missing, and Live Sync working only 50% of the time"; "the Apple Watch app...crashes multiple times every workout"; "I found the workout timer. Cant find how to pause it" — [JustUseApp Strong reviews](https://justuseapp.com/en/app/464254577/strong-workout-tracker-gym-log/reviews); "Reports of data loss ('workouts being lost')" — [Garage Gym Reviews: Strong](https://www.garagegymreviews.com/equipment/strong); watch "rounding to 0.5kg increments (problematic for metric users)" and "occasional Watch-phone sync disconnection" — [The Nerdy Student, 2021](https://www.thenerdystudent.com/2021/08/strong-review/)
- Praise: "The countdown timer helps keep me on track and is easy to adjust while I'm between sets"; "Rest timer is helpful and works great" — [JustUseApp Strong](https://justuseapp.com/en/app/464254577/strong-workout-tracker-gym-log/reviews), [strong.app/love](https://www.strong.app/love)

**Other apps with Lock-Screen timers**
- Alpha Progression: "Rest timer as a Live Activity, so the countdown and your next set sit on the lock screen" and Dynamic Island; alarm when the timer runs out — [Alpha App Store](https://apps.apple.com/us/app/gym-workout-alpha-progression/id1462277793), [Alpha Guide](https://alphaprogression.com/en/blog/alpha-progression-guide)

**Implementation notes (for the developer)**
- Musklr's Live Activity (2026-07-12, updated 2026-08-11): shows exercise, weight × reps, "set 1 of 3", a "Last" value, rest timer with progress bar; requires iOS 16.2 for the Lock Screen card and iPhone 14 Pro+ for Dynamic Island; the −15/+15/skip buttons "open Musklr straight to that action"; "iOS draws the card, not Musklr running in the background, and it only redraws when something changes" — [Musklr blog](https://musklr.com/blog/2026/iphone-lock-screen-workout-tracking-live-activity/)
- Pattern recommended in an open-source tracker's design issue: "Schedule a local notification at T-0 when the set is logged. The visible countdown is derived from a stored end-timestamp" (`endsAt = now + restSeconds`), cancel the notification if the next set is logged early or the app is foregrounded at completion; per-exercise defaults plus a global fallback; keep-awake during workouts — [healthtracker issue #340](https://github.com/NevinJulian/healthtracker/issues/340)
- ActivityKit caveats (Apple dev forum, July 2024, unanswered): `Text(timerInterval:)` counts down live but cannot be custom-formatted; a Live Activity "doesn't automatically end when the timer reaches zero"; `staleDate` only shows a stale UI — [Apple Developer Forums thread 759250](https://developer.apple.com/forums/thread/759250)

### Inferences
- The minimum viable iPhone design is: (1) local notification scheduled at set completion (the real alarm), (2) countdown derived from an end timestamp so it survives backgrounding, (3) a Live Activity with `Text(timerInterval:)` for the Lock Screen / Dynamic Island, with App Intents buttons for −15/+15/skip and "complete set" (Hevy's interactive widget implies iOS 17+ interactive Live Activities). Apple Watch is optional for a solo user given how many complaints target watch sync.
- Because "timer doesn't sound if you're not in the app" is the top Hevy timer complaint, sound should come from the notification (with a custom short sound) rather than in-app audio.

### Gaps
- Neither Strong nor Hevy publishes engineering details (ActivityKit push vs local updates, notification sounds, behaviour after the 8-hour Live Activity limit). Strong's release year for 6.5.0 is not shown on the store page.
- Reddit threads on timer failures could not be fetched (domain blocked); the complaints above come from App Store reviews via JustUseApp.

## Q6. Strong's CSV export: exact columns, formats, and how importers parse it

### Takeaway
There are (at least) two Strong export layouts in the wild. Classic exports are comma-delimited with the header `Date,Workout Name,Duration,Exercise Name,Set Order,Weight,Reps,Distance,Seconds,Notes,Workout Notes,RPE` (weight has no unit column; `Notes`/`Workout Notes` only present when "Include Notes" is on). Exports from Strong 6.2.4+ are semicolon-delimited with quoted fields and the header `"Workout #";"Date";"Workout Name";"Duration (sec)";"Exercise Name";"Set Order";"Weight (kg)";"Reps";"RPE";"Distance (meters)";"Seconds";"Notes";"Workout Notes"`, and include one `Rest Timer` row per exercise. Dates are local `YYYY-MM-DD HH:MM:SS` with no timezone; one row per set; `Set Order` is a 1-based integer per exercise or a tag letter (W/D/F). Hevy imports the file natively (English-only, one import per account) and strong2hevy is a reference open-source importer.

### Cited Findings
**Where the export lives**
- Official: iOS Settings > "Export Strong Data" (Android: Settings > "Export Data"); "spreadsheet friendly CSV format"; "exported files cannot be imported back into Strong" — [Strong Help: Export workout data](https://help.strongapp.io/article/235-export-workout-data)
- Current UI path per third parties: Profile tab > gear > "Export Workouts" (Taper, 2026-07-27) — [Taper: How to export Strong data](https://thetaperapp.com/articles/how-to-export-strong-data/); "Export Workouts under Data Management — turn Include Notes on before exporting... Notes are the one thing you cannot reconstruct afterwards" — [Gript import guide](https://griptapp.com/help/import-from-strong)
- Body measurements export separately as one CSV per metric (e.g., `strong_weight.csv`, `strong_waist.csv`) — [Taper](https://thetaperapp.com/articles/how-to-export-strong-data/)

**Classic (comma) layout — verbatim**
- Header from a real export in a public repo: `Date,Workout Name,Duration,Exercise Name,Set Order,Weight,Reps,Distance,Seconds,Notes,Workout Notes,RPE`; sample rows: `2020-12-30 18:51:52,"Evening Workout",2h 38m,"Snatch (Barbell)",1,40.0,3,0,0,"","",` and `2021-05-13 12:00:00,"Evening Workout",5m,"Swimming",1,0,0,1.0,30,"","",`; RPE column empty throughout; Set Order integers — [StrongAppAnalytics Data/strong.csv](https://github.com/AlexandrosKyriakakis/StrongAppAnalytics/blob/main/Data/strong.csv)
- Same 12 names listed by a user on the Intervals.icu forum: "Date Workout Name Duration Exercise Name Set Order Weight Reps Distance Seconds Notes Workout Notes RPE" — [Intervals.icu forum](https://forum.intervals.icu/t/import-strong-data-weightlifting-app/5531)
- Taper (2026-07) lists 10 headers without the notes columns: "Date, Workout Name, Duration, Exercise Name, Set Order, Weight, Reps, Distance, Seconds, RPE"; timestamps "like 2021-07-24 10:37:18"; Duration "like 1h 9m"; "One row per set, with the workout's details repeated"; "Values are in whatever unit your Strong app is set to log in" with no unit column — [Taper](https://thetaperapp.com/articles/how-to-export-strong-data/)
- A second classic variant documented by Kinoku puts duration last: `Date,Workout Name,Exercise Name,Set Order,Weight,Reps,Distance,Seconds,Notes,Workout Notes,RPE,Workout Duration` — [Kinoku import format](https://kinoku.app/import-format)
- Blog parse notes: "column names have spaces so watch out"; floating-point artefacts like `185.00000000000003`; loaded with pandas `read_csv` (comma) — [AJ's blog: parsing Strong](https://blog.ayjc.net/posts/strong-app-parsing/)

**Strong 6.2.4+ (semicolon) layout — verbatim**
- Header reported 2026-09-23 from a direct export: `"Workout #";"Date";"Workout Name";"Duration (sec)";"Exercise Name";"Set Order";"Weight (kg)";"Reps";"RPE";"Distance (meters)";"Seconds";"Notes";"Workout Notes"`; delimiter `;`; the importer in question rejected it ("File columns are not recognised") — [openGym issue #302](https://github.com/DuarteSantos8/openGym/issues/302)
- Kinoku: "Newer Strong exports (6.2.4+) use semicolon delimiters with quoted fields, include a `Weight (kg)` column, and contain a `Rest Timer` row per exercise"; Kinoku 1.3.0 "drops the weight and turns the rest-timer row into an empty set" (known bug) — [Kinoku import format](https://kinoku.app/import-format)
- Strength Journeys handles "Strong's CSV quirks like semicolon delimiters and weight-unit headers" and references "Rest Timer" rows and "Note" rows — [Strength Journeys: Import Strong](https://www.strengthjourneys.xyz/import/strong)
- Avex importer: "Strong's `Rest Timer` rows are ignored"; rows with distance/duration under a cardio name become cardio; rows without distance are holds — [Avex PR #202](https://github.com/antho976/Avex/pull/202)
- Gript: "Rows labeled Rest Timer are excluded rather than imported as empty timed sets" — [Gript](https://griptapp.com/help/import-from-strong)

**Set Order semantics, units, locale**
- "Set type where Strong marks a set W (warm-up), D (drop set), or F (failure)" in `Set Order`; weight "stores the weight number but not the unit"; a ~2.2× discrepancy after import signals a unit mismatch — [Gript](https://griptapp.com/help/import-from-strong)
- strong2hevy (Go) requires exactly the columns `Date, Workout Name, Duration, Exercise Name, Set Order, Weight, Reps, Distance, Seconds, RPE`; parses dates with layout `2006-01-02 15:04:05` (i.e., `YYYY-MM-DD HH:MM:SS`, no zone — the tool requires an IANA timezone setting to interpret them); parses Duration as space-separated `h`/`m`/`s` segments (tests cover `"1h 17m"`, `"58m"`, `"6m 30s"`); `Set Order = W` → Hevy `warmup`, numeric → normal; other values ("D", "F", "Rest Timer", "Note") are not specially handled; Notes columns are not read; weight converted to `weight_kg` from a configured `lb`/`kg` source unit; fails fast on distance rows unless `distance_unit` (mi/km/m) is set; exercise names are matched by normalised title with a review step (`use-template`, `create-custom`, `skip`); routines can be generated from repeated workout names (opt-in); duplicate prevention via local `import-state.json` hashes — [strong2hevy README](https://github.com/criccomini/strong2hevy), [strong2hevy strong.go](https://raw.githubusercontent.com/criccomini/strong2hevy/main/strong.go), [strong2hevy strong_test.go](https://raw.githubusercontent.com/criccomini/strong2hevy/main/strong_test.go)
- RepStack's failure list: "header names, delimiter issues, locale differences, missing exercise names, or custom exercises that do not map cleanly"; non-English headers; "Decimal commas instead of decimal points"; Set Order "must be numeric and reset per exercise"; Weight and Reps numeric — [RepStack Strong import](https://rep-stack.com/import/strong-csv/)
- Arvo: "The Strong CSV schema is different from Hevy's (different column order, no explicit RPE column in older versions)"; parser "detects the layout from the header row"; locale-aware month names for Hevy — [Arvo blog](https://arvo.guru/blog/hevy-to-arvo-csv-import)
- Kinoku recommends `YYYY-MM-DD HH:MM:SS` dates and accepts "both dots and commas as decimals" — [Kinoku](https://kinoku.app/import-format)

**Hevy's native Strong import**
- Path: Profile > Settings > Export & Import Data > Import Data > Import Strong CSV > Select file; must be "a direct export from the Strong app" and "in English"; "translate the Strong app to English before you export"; support at hello@hevyapp.com — [Hevy Help: Import Strong CSV](https://help.hevyapp.com/hc/en-us/articles/38001424401943-How-to-Import-Strong-App-CSV-Files-and-Export-Your-Data-in-Hevy)
- "Currently, Hevy only allows importing from the Strong app"; "You can only do one data import" (can be reverted); support cannot help with hand-reformatted files — [Hevy Help: Log Previous Workouts and Import CSV](https://help.hevyapp.com/hc/en-us/articles/35687878672663-Tutorial-Log-Previous-Workouts-and-Import-CSV)
- A user who imported ~900 workouts "lost between 5-10 workouts" and found "Some of the workout names are different" after Hevy's import — [AJ's blog: migrate Strong → Hevy](https://blog.ayjc.net/posts/migrate-strong-hevy-app/)
- Liftoff also "imports CSV exports from Strong and Hevy, so your history and PRs come with you" — [Liftoff](https://liftoffrank.com/gamified-workout-tracker); FitNotes iOS accepts Strong/Hevy exports via its own CSV (`Date, Exercise, Category, Weight (kg), Weight (lbs), Reps, Distance, Distance Unit, Time, Notes, Kind`) with warning that "CSVs from some apps are limited in information and you may have to specify the measurement units" — [FitNotes docs](https://www.getfitnotes.com/docs/migrate-from-other-apps.html)

**Hevy export (for a comparable target schema)**
- `workout_data.csv` header: `title,start_time,end_time,description,exercise_title,superset_id,exercise_notes,set_index,set_type,weight_lbs|weight_kg,reps,distance_miles|distance_km,duration_seconds,rpe`; timestamps like `"15 Jul 2026, 09:52"` (quoted, contains a comma); `set_type` ∈ {normal, warmup, dropset, failure}; `superset_id` groups paired exercises; routines are not exported — [Taper: export Hevy data](https://thetaperapp.com/articles/how-to-export-hevy-data/); month names are localised (e.g., "6 Sept. 2026" in German) — [Kinoku](https://kinoku.app/import-format); weight column name follows the account unit — [Avex PR #202](https://github.com/antho976/Avex/pull/202)

### Inferences
- The importer should sniff the delimiter (`,` vs `;`), strip quotes, normalise headers by lower-casing and removing unit suffixes (`Weight (kg)` → weight + unit=kg; `Distance (meters)`; `Duration (sec)` vs `Duration` "1h 9m" vs `Workout Duration`), and treat the presence of `Workout #` as the v6.2.4+ signal. Group rows into workouts by `Workout #` when present, else by (`Date`, `Workout Name`).
- `Set Order` should be parsed as: integer → normal set; `W`/`D`/`F` → warm-up/drop/failure (Gript); `Rest Timer` → per-exercise rest duration (most likely carried in `Seconds`; unverified) to seed template rest times; `Note` rows (mentioned by Strength Journeys) → exercise note. Because tagged sets lose their ordinal, order must be taken from row order within the exercise.
- For a metric iPhone user the new export names the unit in the header, so the unit ambiguity of the classic format is moot; still ask the user to confirm the unit on import if the header is unit-less.

### Gaps
- No source shows a verbatim `Rest Timer` or `Note` data row, so which columns they populate (`Seconds`? `Notes`?) is an inference; the developer should inspect the user's actual file.
- Whether pinned notes, template definitions or set-level RPE-as-decimal appear in the 6.2.4+ export is undocumented. Hevy does not publish which fields its Strong import drops (set tags, notes, custom exercises); the "5–10 lost workouts" report suggests silent row rejection.
- The exact Strong version/date at which the semicolon format was introduced is only known as "6.2.4+" (Kinoku); the openGym report is dated 2026-09-23.

### Inferences
- For a solo, metric, iPhone user coming from Strong, the features to preserve are exactly the praised ones (template one-tap start, pinned notes, previous pre-fill, per-exercise auto timer with warm-up/working split) and the pain points to eliminate are the 3-template cap, the confusing update-template prompt, and timer/sync fragility — the last of which mostly disappears without a watch/cloud sync layer.
